# Phase 1: 会话构建与播种

> 对应 `AgentEngine.run()` 的前置段（engine.py:329-353），进入 30 轮主循环之前的一次性准备。

## 📋 Phase 概述

把请求参数变成"可运行的 Agent 状态"：从提示词里提取可抠图的静态图片、恢复上一次的代码底稿、落盘运行启动记录、经工厂创建带能力门控的提供商会话。

### 🔄 主要逻辑流程

#### 1️⃣ **提取输入图片** (第 99-125 行，调用点 330)
```python
self.tool_runtime.input_images = self._extract_input_images(prompt_messages)
```
- 扫描全部消息的 `image_url` 分量，只放行 `data:image/` 前缀且含逗号的数据 URL——视频复用同一消息形态但被显式排除。

#### 2️⃣ **播种文件状态** (state.py:32-70，调用点 331)
```python
seed_file_state_from_messages(self.file_state, prompt_messages)
```
- 四级优先级链恢复"当前代码"：前端快照 > assistant 历史 > system 标记 > 留空。

#### 3️⃣ **记录启动与创建会话** (第 333-353 行)
```python
self.recorder.record_run_start(model, prompt_messages)
session = create_provider_session(model=model, ..., should_extract_assets=(
    self.should_extract_assets and bool(self.tool_runtime.input_images)))
```
- run_start 落盘 + SQLite 建行；工厂按模型归属建会话，工具可见性由四个能力开关决定。

### 🔄 数据流

```
run(model, prompt_messages)
  │
  ├── 提取输入图片 ──→ tool_runtime.input_images: List[str]
  │                     └── 决定 extract_assets 工具是否被提供
  ├── 播种文件状态 ──→ file_state.content: str（update 场景非空）
  ├── 记录启动    ──→ run_logs/{run_id}/events.jsonl + SQLite runs 行
  └── 创建会话    ──→ session: ProviderSession（持有原生会话容器）
```

## 返回值

本 Phase 无返回值；产物是三个被后续 Phase 消费的状态：`input_images`、`file_state.content`、`session`。

## 总结

1. 📸 输入图片的过滤规则暗含"视频不算素材源"的系统能力边界
2. 🔄 播种让 update 模式无需重传全部代码即可继续编辑
3. 💬 会话工厂的能力门控让模型从第一轮起只看到真正可用的工具
