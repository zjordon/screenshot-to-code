# Phase 5: 结果回填与循环控制

> 对应 `_run_with_session` 的收口（engine.py:325）与循环骨架（engine.py:218-221, 327）。

## 📋 Phase 概述

把本轮的 assistant 轮与全部工具结果写回提供商会话（各家机制不同），随后循环回到 Phase 2 下一轮；30 轮耗尽则熔断。

### 🔄 主要逻辑流程

#### 1️⃣ **工具结果回填** (第 325 行)
```python
await session.append_tool_results(turn, executed_tool_calls)
```
- 三家各自把"assistant 轮 + 工具结果"追加进原生容器；工具图片按各家多模态规范注入。

#### 2️⃣ **轮次控制与上限熔断** (第 218-221, 327 行)
```python
max_steps = 30
for _ in range(max_steps):
    ...
raise Exception("Agent exceeded max tool turns")
```
- for-range 而非 while——轮数上限在结构上保证；耗尽即抛通用异常。

### 🔄 数据流

```
executed_tool_calls
  │
  └── append_tool_results
        ├── OpenAI:   _input_items += [assistant items, function_call_output...]
        ├── Anthropic: _messages  += [assistant(text+tool_use), user(tool_result)]
        └── Gemini:    _contents  += [原生Content, FunctionResponse parts]
              │
              ▼
      循环回到 Phase 2（下一轮 stream_turn 携带全部历史）
              │
      └── 30 轮耗尽 → Exception("Agent exceeded max tool turns")
```

## 返回值

无（循环继续或抛异常）。

## 总结

1. 🔄 回填是"会话记忆"的唯一写入点——图片、错误、diff 全部进上下文
2. 🎯 for-range 循环让上限不可绕过（无 step++ 遗漏风险）
3. ⚠️ 轮次耗尽用通用 Exception 而非专用类——下游与普通失败同待遇（eval 可重试）
