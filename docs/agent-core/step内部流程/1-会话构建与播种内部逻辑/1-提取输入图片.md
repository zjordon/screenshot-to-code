# 提取输入图片 — `_extract_input_images()`

### 📋 **方法作用**

从完整提示词消息中筛出"可以作为素材提取原料"的静态图片数据 URL，注入工具运行时——这一步直接决定 `extract_assets` 工具在本轮 run 中是否可用。

---

### 🔄 **主要逻辑流程**

#### **1️⃣ 遍历消息与分量（第 100-107 行）**

```python
for message in prompt_messages:
    content = message.get("content")
    if not isinstance(content, list):
        continue        # 纯文本消息直接跳过
    for part in content:
        if not isinstance(part, dict) or part.get("type") != "image_url":
            continue    # 只关心 image_url 分量
```

- 输入是 OpenAI Chat 规范格式的消息列表；图片一律以 `image_url` 分量携带（含 data URL 与视频）。

#### **2️⃣ 形态校验（第 108-124 行）**

```python
image_url = part.get("image_url")
if not isinstance(image_url, dict):
    continue
url = cast(object, image_url.get("url"))
# Video parts use the OpenAI-compatible `image_url` shape too,
# but extract_assets can only crop still-image data URLs.
if (isinstance(url, str)
        and url.startswith("data:image/")
        and "," in url):
    images.append(url)
```

**✅ 接受条件（三连）：**
- `url` 是字符串
- 以 `data:image/` 开头（内联 base64，非 http 链接）
- 含 `,`（头部与数据段的分隔符存在，即格式完整）

**❌ 拒绝形态与理由：**
| 形态 | 拒绝理由 |
|------|---------|
| `data:video/webm;...` 视频 | Gemini 视频复用 image_url 形态，但素材裁剪只能处理静态图 |
| `http(s)://...` 远程图 | 抠图管线需要本地像素（EXIF 转正/PNG 统一），远程 URL 无从处理 |
| 厂商原生对象 | 形态不符，静默跳过 |

---

### 🎯 **设计亮点**

1. **能力即数据**：不在工具执行时才发现"没有可用原料"，而是在 run 开始就把原料清单备好——下游 `create_provider_session` 的 `should_extract_assets and bool(input_images)` 双重条件据此决定是否向模型提供工具（engine.py:349-351 注释明言视频输入不暴露注定失败的工具）。
2. **与记录器的镜像实现**：`agent_runs.py:194-226` 的 `_first_input_image_sha256` 复制了同一过滤逻辑（防 import 环），两者必须同步修改——这是复制式去环的维护代价。

---

### 📊 **返回值结构**

| 字段 | 类型 | 说明 |
|------|------|------|
| 返回值 | `List[str]` | 完整 data URL 列表（保序、不去重——重复图由素材存储的 sha256 去重兜底） |

---

### 💡 **典型使用场景**

- 图片模式：用户拖入 1-5 张截图 → 全部入选，extract_assets 可用。
- 视频模式：webm data URL → 全部被拒，视频由 Gemini 原生理解，抠图工具不出现。
- 文本模式：无图片 → 空列表。
