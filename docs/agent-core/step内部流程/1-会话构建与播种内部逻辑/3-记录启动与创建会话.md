# 记录启动与创建会话 — `record_run_start` + `create_provider_session`

> 源码: `backend/agent/engine.py:333-353`、`backend/agent/providers/factory.py:19-80`、`backend/fs_logging/agent_runs.py:343-396`

### 📋 **方法作用**

run 的最后两步准备：把启动事件写入运行档案（评测矩阵的可匹配性在此建立），再经工厂创建带能力门控的提供商会话。

---

### 🔄 **主要逻辑流程**

#### **1️⃣ 记录启动（engine.py:333-334 → agent_runs.py:343-396）**

```python
if self.recorder is not None:
    self.recorder.record_run_start(model, prompt_messages)
```

**record_run_start 内部三件事：**
| 动作 | 落点 | 说明 |
|------|------|------|
| 记时起点 + 元数据 | 内存 | `_run_started_mono`、provider 归属（MODEL_PROVIDER 表） |
| `run_start` 事件 | events.jsonl | 含**完整 prompt_messages** 与 `input_image_sha256` |
| INSERT runs 行 | SQLite | status='running'——终态由 record_run_end 更新 |

**📝 关键点：** `input_image_sha256`（首图字节摘要）是评测矩阵把"UI 运行"与"eval 输入文件"对上的匹配键（evals 的输入是磁盘 PNG 的 base64 原文，摘要天然相等）。

#### **2️⃣ 工厂建会话（engine.py:336-353 → factory.py:19-80）**

```python
session = create_provider_session(
    model=model,
    prompt_messages=prompt_messages,
    ...,
    should_extract_assets=(
        self.should_extract_assets and bool(self.tool_runtime.input_images)
    ),
    recorder=self.recorder,
)
```

**决策树（factory.py:31-80）：**
```
canonical_tool_definitions(四个门控)
  ├─ image_generation_enabled   ← 请求开关
  ├─ image_editing_enabled      ← replicate key（参数或 env）
  ├─ asset_extraction_enabled   ← gemini key 且 本方法传入"请求要求且有原料"
  └─ screenshot_enabled         ← 启动时 Chromium 探测缓存
       │
       ├─ model ∈ OPENAI_MODELS    → 缺 key 即 raise → OpenAIProviderSession
       ├─ model ∈ ANTHROPIC_MODELS → 缺 key 即 raise → AnthropicProviderSession
       ├─ model ∈ GEMINI_MODELS    → 缺 key 即 raise → GeminiProviderSession
       └─ 其它 → ValueError
```

**验证逻辑：**
- 三分支都是**先检查 key 再建客户端**——早失败，避免循环中途才炸。
- 工具 schema 在此一次性序列化（各家 `serialize_*_tools`），之后轮次复用。

---

### 🎯 **设计亮点**

1. **记录先于一切**：即使后续工厂抛错，run_start 已落盘——run 记录能如实反映"启动即失败"而非凭空消失。
2. **门控的复合条件**：`asset_extraction_enabled = 请求要求 and 有 gemini key and 有静态输入图`——三方缺一即不给工具，模型永远不会看到注定失败的工具（engine.py:344-348 注释）。
3. **归属查表不猜名**：`MODEL_PROVIDER` 显式映射，新增模型不碰工厂逻辑。

### 📊 **返回值结构**

| 字段 | 类型 | 说明 |
|------|------|------|
| `session` | `ProviderSession` | 满足四方法协议的会话实例；构造时已完成消息格式转换（OpenAI input_items / Claude system+messages / Gemini contents） |

### 💡 **典型使用场景**

- 每个变体一次；四个变体即四次独立会话（互不共享上下文）。
- 评测路径同链路（evals/core.py 复用 Agent + recorder），保证评测结论可迁移。
