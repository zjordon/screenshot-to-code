# 播种文件状态 — `seed_file_state_from_messages()`

> 源码: `backend/agent/state.py:32-70`

### 📋 **方法作用**

在主循环开始前把"上一次的代码"恢复进 `AgentFileState`，让 update 模式有底稿可增量编辑——这是服务端无会话架构下重建工作现场的机制。

---

### 🔄 **主要逻辑流程**

#### **1️⃣ 已有内容短路（第 36-38 行）**

**✅ file_state.content 非空：**
- 直接返回——构造函数已用 `initial_file_state`（前端传来的当前代码快照）播种，最高优先级。

#### **2️⃣ 路径一：倒序扫 assistant 历史（第 39-49 行）**

```python
for message in reversed(prompt_messages):
    if message.get("role") != "assistant":
        continue
    raw_text = extract_text_content(message)
    if not raw_text:
        continue
    extracted = extract_html_content(raw_text)
    file_state.content = extracted or raw_text   # 剥不出就原文接受
    return
```

**关键参数说明：**
| 步骤 | 说明 |
|------|------|
| `reversed` | 取**最近**一次 assistant 产物（多轮编辑后最新版本） |
| `extract_html_content` | 剥 `<file path>` 标签 → markdown 围栏 → `<html>...</html>`（codegen/utils.py） |
| `extracted or raw_text` | 兜底接受原文——空内容会被 `EmptyOutputError` 判死，宁可多不可空 |

#### **3️⃣ 路径二：system 消息标记截取（第 51-70 行）**

```python
system_message = prompt_messages[0]
if system_message.get("role") != "system":
    return
markers = ["Here is the code of the app:"]
raw_text = system_text.split(marker, 1)[1].strip()
```

**验证逻辑：**
- 只检查 messages[0] 且必须是 system 角色；
- 标记由 `prompts/update/from_file_snapshot.py` 在组装提示词时写入（代码快照嵌在 system 尾部）；
- 标记之后的全部文本视为底稿，同样走 `extract_html_content or 原文`。

---

### 🎯 **设计亮点**

1. **四级优先级链**: `initial_file_state`（前端快照）> assistant 历史（多轮对话）> system 标记（快照模式）> 空（全新创建）——三种 update 形态全覆盖，且永不覆盖已有内容（短路在最前）。
2. **标记而非结构**: 用字符串标记分割而非独立消息字段——兼容 OpenAI 消息规范的同时避免了自定义 schema 的跨厂商序列化问题。

---

### 📊 **返回值结构**

| 字段 | 类型 | 说明 |
|------|------|------|
| 返回值 | `None` | 副作用写入 `file_state.content`（与 `file_state.path`，缺省补 `index.html`） |

---

### 💡 **典型使用场景**

- 多轮编辑：第 3 轮"再改改按钮"→ 从第 2 轮 assistant 产物恢复。
- 快照编辑：前端只传当前代码（fileState）→ system 标记路径。
- 全新创建：两条路径都空 → content 留空，等待 create_file。
