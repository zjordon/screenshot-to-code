# 工具结果回填 — `append_tool_results` 的三家实现对照

> 调用点: `backend/agent/engine.py:325`；实现: openai.py:496-534 / anthropic/provider.py:445-494 / gemini.py:404-444

### 📋 **方法作用**

把本轮的 assistant 轮（原生对象）与全部工具结果（含图片）追加进各自会话容器——下一轮 `stream_turn` 因此"记得"本轮发生的一切。

---

### 🔄 **主要逻辑流程**

#### **1️⃣ 共同骨架**

```
① 追加 assistant 轮（各家用 ProviderTurn.assistant_turn 的原生形态）
② 逐 executed 组装结果项（完整 result JSON + 图片注入）
③ 追加为"工具结果"角色的消息/项
```

#### **2️⃣ 三家差异对照**

| 维度 | OpenAI (L496-534) | Anthropic (L445-494) | Gemini (L404-444) |
|------|-------------------|----------------------|-------------------|
| assistant 轮 | `turn.assistant_turn`（output_items 列表）直接 extend | 手工重建 text + tool_use 块 | 校验后 append 原生 Content（**保 thought signature**） |
| 结果项类型 | `function_call_output`（call_id 匹配） | `tool_result`（tool_use_id + is_error） | `FunctionResponse`（id + name） |
| 文本载荷 | result JSON（input_text 分量） | result JSON（text 块） | `response=result`（结构化 dict 直传，非字符串） |
| 图片注入 | output 数组混排 `input_image` | content 数组 append image 块（URL source 或 base64） | FunctionResponse.parts 内联 bytes（**URL 需先下载**） |
| 失败语义 | JSON 内 error 字段 | `is_error=True` 且**强制纯文本** | result dict 内 error 字段 |
| 独有动作 | — | 追加后再查 20 图限流 | `_resolve_part_bytes` 下载公共 URL（30s 超时） |

#### **3️⃣ 图片注入的三种哲学**

**✅ OpenAI**：文本与图片同一 output 数组混排——模型并读。
**✅ Anthropic**：图片块紧跟其后；但 `is_error=True` 时 API 拒绝非文本——失败只给 JSON 文本（provider.py:473-475 注释）。
**✅ Gemini**：只收 bytes——公共 URL（如 replicate.delivery）必须先 httpx 下载再内联；下载失败跳过该图并打印（gemini.py:400-401），不失败整个回填。

---

### 🎯 **设计亮点**

1. **错误双通道（Anthropic 独有）**：`is_error` 协议标志 + JSON 内容字段，模型两条路感知失败。
2. **Gemini 的结构化直传**：response 是 dict 而非 JSON 字符串——省一次序列化/解析，且 SDK 保真。
3. **回填即缓存命中**：Anthropic 的 `cache_control: ephemeral` 加在 system 上，回填不改前缀——多轮续跑时提示词缓存持续命中（成本观测里的 cache_read 来源）。
