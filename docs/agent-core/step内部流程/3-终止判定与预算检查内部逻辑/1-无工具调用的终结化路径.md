# 无工具调用的终结化路径 — `_finalize_response()`

> 源码: `backend/agent/engine.py:264-265`（触发点）、`engine.py:375-386`（实现）

### 📋 **方法作用**

模型不再调用工具（给出最终回答）时的循环出口：确定最终 HTML 的权威来源并补发前端。

---

### 🔄 **主要逻辑流程**

#### **1️⃣ 触发判定（第 264-265 行）**

```python
if not turn.tool_calls:
    return await self._finalize_response(turn.assistant_text)
```

- 空列表即终点——模型用纯文本宣告完成（"I've created..." 之类的总结语）。

#### **2️⃣ 权威来源裁决（第 375-386 行）**

```python
async def _finalize_response(self, assistant_text: str) -> str:
    if self.file_state.content:          # ① 工具产物优先
        return self.file_state.content

    html = extract_html_content(assistant_text)   # ② 正文兜底
    if html:
        self.file_state.content = html
        await self._send("setCode", html)          # 补发给前端
        if self.recorder is not None:
            self.recorder.record_set_code(len(html), "finalize")
    return self.file_state.content
```

**✅ 路径 ①（常态）：** 模型此前已调过 create_file/edit_file——file_state 即权威，直接返回（前端早已通过流式预览看到内容，无需重发）。

**❌ 路径 ②（兜底）：** 模型把 HTML 直接写在正文里却没调工具——从正文剥离 HTML、写入 file_state、**补发 setCode**（否则前端空白）、记录 `record_set_code(source="finalize")`。

#### **3️⃣ 空串后果（engine.py:356-357）**

- 返回空串 → run() 的 `if not result: raise EmptyOutputError()`——终结化不豁免空输出判定。

---

### 🎯 **设计亮点**

1. **产物优先于言辞**：file_state（工具写的）永远压过 assistant_text（模型说的）——防止模型在正文里重复/改写代码造成前后不一致。
2. **兜底也要闭环**：路径 ② 不只是提取，还负责补发前端与记录——三条记录源（stream_preview/tool_result/finalize）在 run 档案里可追溯。

---

### 📊 **返回值结构**

| 字段 | 类型 | 说明 |
|------|------|------|
| 返回值 | `str` | 最终 HTML；可能为空串（由上层判定为 EmptyOutputError） |

---

### 💡 **典型使用场景**

- 正常完成轮：模型调完 screenshot_preview 自检满意后，回一句总结 → 路径 ①。
- 极简任务（text 模式一句话生成小页面）：模型直接正文出码 → 路径 ②。

### 🔗 **与其他方法的协作**

```

```
