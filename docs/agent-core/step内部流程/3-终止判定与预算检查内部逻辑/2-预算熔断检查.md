# 预算熔断检查 — `BudgetExceededError` 的产生点

> 源码: `backend/agent/engine.py:267-276`；异常定义 `engine.py:38-48`；上限常量 `backend/config.py:23`

### 📋 **方法作用**

在"模型还想继续"的每个轮次边界查询累计花费，超过 `GENERATION_MAX_COST_USD = 3.0` 即中止变体——单路变体的硬性资源护栏。

---

### 🔄 **主要逻辑流程**

#### **1️⃣ 查询累计花费（第 270 行）**

```python
spent = session.total_cost_usd()
```

**关键参数说明：**
| 情形 | total_cost_usd 返回 | 含义 |
|------|--------------------|------|
| 模型有定价（MODEL_PRICING 命中） | `float`（跨轮累计） | 参与熔断判定 |
| 模型无定价 | `None` | **不设限**——新模型未录价时不会误杀 |

- 花费 = 每次 `record_llm_response` 时 `usage.cost(pricing)` 的累加（Provider 内部 `_total_usage`）。

#### **2️⃣ 熔断判定（第 271-276 行）**

```python
# Abort only when the run would otherwise continue: a run that
# just produced its final answer is already paid for.
if spent is not None and spent > GENERATION_MAX_COST_USD:
    print(f"[BUDGET] Aborting variant {self.variant_index}: "
          f"${spent:.2f} > ${GENERATION_MAX_COST_USD:.2f}")
    raise BudgetExceededError()
```

**验证逻辑：**
- 检查点位于"无工具调用判定"**之后**——本轮已是最终答案则不再检查（那轮的钱已花掉，拦也收不回）；
- 精确金额只进后端日志与 run 记录；异常文案不含金额（见下）。

#### **3️⃣ 异常的下游语义（engine.py:38-48）**

```python
class BudgetExceededError(Exception):
    def __init__(self) -> None:
        super().__init__(
            "Generation stopped: this variant exceeded its resource limit."
        )
```

**📝 下游差异化处理：**
| 消费方 | 行为 |
|--------|------|
| `_run_variant`（generate_code.py:709-713） | 通用 except 翻译 → 前端 variantError 显示异常文案 |
| eval runner（evals/runner.py） | 捕获后**不重试**（对比：普通失败重试 MAX_EVAL_RETRIES=2 次）——预算耗尽重跑必然再超 |
| run 记录 | record_run_end("failed", error=...) 留档确切原因 |

---

### 🎯 **设计亮点**

1. **文案与数据分离**：用户可见文案刻意模糊（"resource limit"），确切金额只在 `[BUDGET]` 日志与 run.json——避免用户横向比较"我这次花了 $2.87"之类的噪声。
2. **None 即放行的三态设计**：`None / ≤3 / >3` 对应"不设限 / 继续 / 熔断"，未定价模型天然豁免而非报错。
3. **轮次边界检查**：不是每次 LLM 调用后都拦，而是在"还要付下一轮钱"的决策点上拦——最小化对正常流的干扰。

---

### 📊 **返回值结构**

| 字段 | 类型 | 说明 |
|------|------|------|
| 正常通过 | `None` | 隐式继续 Phase 4 |
| 熔断 | `BudgetExceededError` | 无参构造，文案固定 |

---

### 💡 **典型使用场景**

- 高思考档位模型（如 sol max）在复杂截图上反复 extract_assets + edit_file 打转时，最可能在 8-15 轮触顶。
- 4 变体并行时每变体独立 $3 上限——一次生成请求的理论上限约 $12。

---

### 🔗 **与其他方法的协作**

```
session.total_cost_usd
  └── TokenUsage.cost ← MODEL_PRICING（按 api 模型名）
        │
        ▼
本检查点（轮次边界）
  ├── 通过 → session.append_tool_results（Phase 5）
  └── 熔断 → BudgetExceededError
        ├── run() BaseException 兜底 → record_run_end("failed")
        ├── _run_variant → variantError（前端）
        └── eval runner → 不重试
```
