# 异常兜底与会话关闭 — BaseException 捕获与 finally

> 源码: `backend/agent/engine.py:361-373`

### 📋 **方法作用**

任何失败路径（含客户端取消）的统一出口：把错误落盘成 failed 终态后**原样重抛**，finally 无条件关闭会话——run 档案永不悬挂、网络资源永不泄漏。

---

### 🔄 **主要逻辑流程**

#### **1️⃣ BaseException 兜底（第 361-371 行）**

```python
# BaseException so cancellation (client disconnect) still finalizes
# the run record instead of leaving it stuck at "running".
except BaseException as exc:
    if self.recorder is not None:
        await self.recorder.record_run_end(
            "failed",
            error="".join(
                traceback.format_exception_only(type(exc), exc)
            ).strip(),
        )
    raise
```

**✅ 为什么要 BaseException：**

| 异常 | 是否 Exception 子类 | 普通 except 能否捕获 |
|------|--------------------|--------------------|
| EmptyOutputError / BudgetExceededError / 提供商错误 | 是 | 能 |
| `asyncio.CancelledError`（用户关页面/Stop） | **否**（Python 3.8+ 直接继承 BaseException） | **不能** |

- 漏捕 CancelledError 的后果：SQLite 里 run 停在 `status='running'`，评测矩阵把它当"在跑"永久悬挂。

**📝 error 字段格式：** `format_exception_only` 只取"类型: 消息"一行（如 `agent.engine.BudgetExceededError: Generation stopped: ...`），不带全栈——run.json 简洁，栈在事件流里可重建。

#### **2️⃣ 重抛而非吞掉（`raise`）**

- 失败语义交还上层：`_run_variant` 翻译成 variantError / eval runner 决定重试 / asyncio 感知取消。
- 兜底段只做"记录"这一件事——不改变异常的传播路径。

#### **3️⃣ finally 关闭（第 372-373 行）**

```python
finally:
    await session.close()
```

**close() 的三家行为（共同点：打印 `[TOKEN USAGE]` 行）：**
| Provider | 额外动作 |
|----------|---------|
| OpenAI | `await self._client.close()`（关闭 httpx 连接池） |
| Anthropic | 同上 |
| Gemini | 无显式关闭（genai Client 无连接池 API） |

- `[TOKEN USAGE] provider=... input=... output=... cache_read=... cost=$...` 是运维排查成本问题的第一落点。

---

### 🎯 **设计亮点**

1. **记录-传播解耦**：兜底段补齐档案后 `raise` 原样交还——观测完整性不以吞异常为代价。
2. **finally 的必然性**：成功/失败/取消三路都汇到同一关闭点——无泄漏分支。

---

### 📊 **返回值结构**

| 字段 | 类型 | 说明 |
|------|------|------|
| 本段 | 无返回 | `raise` 传播原异常；副作用是 run 档案终态化 + 会话关闭 |

---

### 💡 **典型使用场景**

- 用户生成中途关闭页面 → 前端 ws.close(4333) → asyncio 取消变体 task → 本兜底落盘 failed → agent-runs 前端可见该 run 的 cancellation 证据。

---

### 🔗 **与其他方法的协作**

```
任意异常 / CancelledError
        │
        ▼
except BaseException
  ├── traceback.format_exception_only → error 一行
  ├── recorder.record_run_end("failed")
  │     └── SQLite: status running → failed
  └── raise
        │
        ▼
finally: session.close()
  └── print [TOKEN USAGE] ... + client.close()
        │
        ▼
上层：_run_variant except → variantError（或 eval 重试判断）
```
