# 流式代码预览 — `_stream_code_preview()`

> 源码: `backend/agent/engine.py:291-294`（触发）、`engine.py:139-168`（实现）

### 📋 **方法作用**

create_file 的工具参数已完整（模型流式写完了），在**真正执行前**把内容分块回放给前端——让预览以受控节奏"逐步成形"，而非一帧砸出全部内容。

---

### 🔄 **主要逻辑流程**

#### **1️⃣ 触发条件（第 291-294 行）**

```python
if tool_call.name == "create_file":
    content = extract_content_from_args(tool_call.arguments)
    if content:
        await self._stream_code_preview(tool_event_id, content)
```

- 仅 create_file 享有此待遇；`extract_content_from_args` 此时拿到的是**定稿 dict**（Provider 已解析），直接 `.get("content")`。

#### **2️⃣ 增量计算（第 146-158 行）**

```python
already_sent = self._tool_preview_lengths.get(tool_event_id, 0)
total_len = len(content)
if already_sent >= total_len:
    return              # 流式阶段已全部发过，跳过

max_chunks = 18
min_step = 200
step = max(min_step, total_len // max_chunks)
```

**关键参数说明：**
| 参数 | 值 | 含义 |
|------|-----|------|
| `max_chunks` | 18 | 回放最多 18 帧 |
| `min_step` | 200 | 每帧至少 200 字符（小文件一帧发完） |
| `step` | `max(200, len//18)` | 大文件按 1/18 均分 |

#### **3️⃣ 分块发送（第 160-166 行）**

```python
for end in range(start + step, total_len, step):
    await self._send("setCode", content[:end])     # 前缀式快照
    self._mark_preview_length(tool_event_id, end)
    await asyncio.sleep(0.01)                       # 10ms 节拍

await self._send("setCode", content)                # 末帧全量
self._mark_preview_length(tool_event_id, total_len)
self.recorder.record_set_code(total_len, "stream_preview")
```

**验证逻辑：**
- 从"已发长度"处续播——与 Phase 2 流式预览（40 字符粒度）无缝衔接，不重发已见前缀；
- `setCode` 语义是**全量替换**，所以每帧发 `content[:end]` 前缀；
- `_mark_preview_length` 只增不减（L139-144）。

---

### 🎯 **设计亮点**

1. **两级流式**：Phase 2 的 delta 预览（跟着模型打字机）+ 本步骤的回放预览（工具确认后的平滑动画）——即使模型瞬间吐完参数，前端仍有"生成感"。
2. **10ms 节拍器**：`asyncio.sleep(0.01)` 让出事件循环——18 帧 × 10ms 的动画开销约 180ms，可接受且不阻塞其它变体的消息。
3. **记账防重**：`_tool_preview_lengths` 跨步骤共享，两个预览源对同一 eventId 永不重发。

---

### 📊 **返回值结构**

| 字段 | 类型 | 说明 |
|------|------|------|
| 前端消息序列 | `{type:"setCode", value:前缀}` × N 帧 + 末帧全量 | variantIndex 定向 |

---

### 💡 **典型使用场景**

- 40KB 的 HTML：流式阶段发了部分 → 回放补足剩余（step≈2.2KB × 18 帧）。
- 极小文件（<200 字符）：一帧直接全量。

### 🔗 **与其他方法的协作**

```

```
