# 工具执行与记录 — `tool_runtime.execute` 的计时边界

> 源码: `backend/agent/engine.py:296-304`

### 📋 **方法作用**

真正执行工具的六行代码：记录起止包裹执行，产出 `ToolExecutionResult`——注释明确说明计时起点刻意选在预览之后。

---

### 🔄 **主要逻辑流程**

#### **1️⃣ 计时边界的注释（第 296-299 行）**

```python
# Timing starts here, after the cosmetic preview stream, so
# tool durations measure execution only.
if self.recorder is not None:
    self.recorder.record_tool_start(tool_event_id, tool_call)
```

**✅ 设计意图：**
- `_stream_code_preview`（装饰性回放，含 18×10ms 动画）**不计入**工具耗时；
- run.json 里 `tool_time_ms` 反映真实执行成本（Replicate 轮询、Chromium 渲染等）。

#### **2️⃣ 执行（第 300 行）**

```python
tool_result = await self.tool_runtime.execute(tool_call)
```

**执行契约（runtime.py:56-99，详见职责文档）：**
- 任何工具内错误都转为 `ok=False` 的返回值——**这一行永不抛异常**（除非 bug）；
- INVALID_JSON 参数在此被前置拦截。

#### **3️⃣ 终止记录（第 301-304 行）**

```python
self.recorder.record_tool_end(tool_event_id, tool_call, tool_result)
```

**record_tool_end 副作用（agent_runs.py:588-643）：**
| 动作 | 落点 |
|------|------|
| duration_ms = now - tool_started_mono | events.jsonl + tool_time_ms 累计 |
| 完整 result + summary + updated_content_len | `tool_call_end` 事件 |
| multimodal 元数据（只记 data_len/URL，不重复存 bytes） | 同上 |
| 易失 URL 检测 → 后台下载任务 | tool_assets/（fire-and-forget） |

---

### 🎯 **设计亮点**

1. **三明治式记录**：start/end 夹住 execute，异常也不丢 end——`record_tool_end` 若因异常跳过，`_tool_started_mono.pop` 不会执行，但 run_end 汇总以实际到达的 end 事件为准（少记一个不致命）。
2. **bytes 不双写**：工具图片 bytes 已在下轮 `llm_call_start` 的请求载荷里 base64 出现，tool_call_end 只记长度元数据——档案体积控制。
3. **易失资产抢救点**：replicate.delivery URL 在此刻（产出瞬间）就被排入后台下载，等 run 结束再下可能已过期（~1 小时寿命）。
