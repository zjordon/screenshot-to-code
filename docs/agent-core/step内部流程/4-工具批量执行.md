# Phase 4: 工具批量执行

> 对应 `_run_with_session` 每轮迭代的执行段（engine.py:278-323）。

## 📋 Phase 概述

"行动半场"：对本轮的每个 tool_call 依次做四件事——广播启动、（若是 create_file）回放式预览、执行并记录、广播结果。所有前端可见的工具活动与产物更新都发生在这里。

### 🔄 主要逻辑流程

#### 1️⃣ **工具启动广播** (第 278-289 行)
```python
tool_event_id = tool_call.id or self._next_event_id("tool")
if tool_event_id not in started_tool_ids:
    await self._send("toolStart", data={"name": ..., "input": summarize_tool_input(...)})
```
- 与流式预告共享 ID 去重；输入经摘要器压缩（create_file 只发 200 字预览不发全文）。

#### 2️⃣ **流式代码预览** (第 291-294 行 → L146-168)
```python
if tool_call.name == "create_file":
    content = extract_content_from_args(tool_call.arguments)
    if content:
        await self._stream_code_preview(tool_event_id, content)
```
- 工具还没执行，先把模型写好的内容分块回放给前端。

#### 3️⃣ **工具执行与记录** (第 296-304 行)
```python
self.recorder.record_tool_start(tool_event_id, tool_call)
tool_result = await self.tool_runtime.execute(tool_call)
self.recorder.record_tool_end(tool_event_id, tool_call, tool_result)
```
- 计时边界刻意从预览之后开始——工具耗时只计执行本身。

#### 4️⃣ **结果广播** (第 305-323 行)
```python
if tool_result.updated_content:
    await self._send("setCode", tool_result.updated_content)
await self._send("toolResult", data={"name": ..., "output": tool_result.summary, "ok": ...})
```
- 产物经 setCode 全量替换；结果摘要（非完整 result）给前端。

### 🔄 数据流

```
for tool_call in turn.tool_calls:
  │
  ├── ① toolStart(name + 摘要input) ──────→ 前端活动条目
  ├── ② create_file? → 分块 setCode ─────→ 前端预览成形
  ├── ③ execute → ToolExecutionResult ───→ (ok/result/summary/updated/multimodal)
  │      └── record_tool_start/end ───────→ events.jsonl + 耗时
  └── ④ updated_content → setCode ───────→ 前端最终内容
         summary+ok → toolResult ────────→ 前端活动完结
  │
  └── ExecutedToolCall 累积 → Phase 5 回填
```

## 返回值

累积的 `executed_tool_calls: List[ExecutedToolCall]`，交 Phase 5 写回会话。

## 总结

1. 🔄 四步节奏对每个工具重复——前端的活动条目/代码区/记录档案三线同步更新
2. 📸 "预告-执行-定稿"三段式让 create_file 体验上零等待
3. 📊 result 给模型（回填）、summary 给前端（展示）——双投影一次产出
