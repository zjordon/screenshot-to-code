## 1. 快速开始

### 1.1 环境要求

| 要求 | 版本 | 说明 |
|------|------|------|
| Python | ^3.10（实际虚拟环境为 3.12） | 后端，Poetry 管理 |
| Poetry | 最新 | 后端包管理器（`pip install --upgrade poetry`） |
| Node.js | >= 14.18（建议 20+） | 前端 |
| pnpm | 10.32.1（packageManager 字段锁定） | 前端包管理器 |
| LLM API key | 至少 1 个 | OpenAI / Anthropic / Gemini 三选一 |
| Chromium | 可选 | `poetry run playwright install chromium`，启用截图自检工具 |
| Docker | 可选 | 一键部署方式 |

### 1.2 安装

```bash
# 1) 克隆
git clone https://github.com/abi/screenshot-to-code.git
cd screenshot-to-code

# 2) 配置后端 key（backend/.env，至少一个）
cd backend
echo "OPENAI_API_KEY=sk-your-key"  >  .env
echo "ANTHROPIC_API_KEY=your-key"  >> .env
echo "GEMINI_API_KEY=your-key"     >> .env   # 强烈推荐
echo "REPLICATE_API_KEY=r8_your-key" >> .env # 推荐：图片生成/编辑/去背景

# 3) 安装后端依赖
poetry install
poetry run playwright install chromium   # 可选；Linux 加 --with-deps

# 4) 安装前端依赖
cd ../frontend
pnpm install
```

> **Windows 用户注意**: `.env` 文件必须保存为 **UTF-8（无 BOM）** 编码，否则会报 UTF-8 相关错误（README FAQ 明确提及：用 Notepad++ → Encoding → UTF-8）。

### 1.3 快速运行

```bash
# 终端 1：后端（端口 7001）
cd backend
poetry run uvicorn main:app --reload --port 7001

# 终端 2：前端（端口 5173）
cd frontend
pnpm dev
```

打开 **http://localhost:5173**（注意用 `localhost` 而非 `127.0.0.1`，Vite dev server 只绑定 localhost）。

Docker 方式（根目录）：

```bash
echo "OPENAI_API_KEY=sk-your-key" > .env
docker-compose up -d --build      # http://localhost:5173
```

Docker 模式适合体验，不适合开发（文件变更不触发重建）。

## 2. 配置说明

### 2.1 后端环境变量（backend/.env）

| 变量 | 必需 | 默认 | 说明 |
|------|------|------|------|
| `OPENAI_API_KEY` | 三选一 | - | GPT 系列代码生成 |
| `ANTHROPIC_API_KEY` | 三选一 | - | Claude 系列代码生成 |
| `GEMINI_API_KEY` | 三选一（**强烈推荐**） | - | Gemini 系列 + 素材提取 + **视频模式必需** |
| `REPLICATE_API_KEY` | 推荐 | - | 图片生成/编辑/去背景；**只能配在 .env，不支持 UI 设置** |
| `OPENAI_BASE_URL` | 可选 | 官方地址 | OpenAI 代理，路径须含 `/v1`；生产模式禁用 |
| `IS_DEBUG_ENABLED` | 可选 | false | 调试输出开关 |
| `DEBUG_DIR` | 可选 | "" | 调试输出目录 |
| `PROMPT_REPORTS_ENABLED` | 可选 | false | 每次 LLM 请求写入 run_logs/prompt_reports，可在 `/evals/prompt-reports` 页查看 |
| `LOCAL_ASSET_DIR` | 可选 | backend/local_assets | 本地素材目录 |
| `LOCAL_ASSET_BASE_URL` | 可选 | http://127.0.0.1:7001 | 素材服务基础 URL（evals 场景用） |
| `IS_PROD` | 可选 | false | 托管版功能开关 |

另有一个硬编码常量 `GENERATION_MAX_COST_USD = 3.0`（backend/config.py:23）：单变体生成花费熔断上限。

### 2.2 前端环境变量（frontend/.env.local / .env.example）

| 变量 | 默认 | 说明 |
|------|------|------|
| `VITE_WS_BACKEND_URL` | ws://127.0.0.1:7001 | WebSocket 后端地址（改后端端口时必须同步改） |
| `VITE_HTTP_BACKEND_URL` | 同源 | HTTP 后端地址 |
| `VITE_IS_DEPLOYED` | 未设 | 云部署模式（ToS 弹窗、统计注入） |
| `VITE_PICO_BACKEND_FORM_SECRET` | 未设 | ToS 表单提交密钥 |
| `PROXY_CODEGEN_BACKEND` | http://127.0.0.1:7001 | Vite dev 代理目标（vite.config.ts） |

### 2.3 运行时配置优先级

- **API key**: 前端设置对话框（齿轮图标，存浏览器 localStorage）> `backend/.env`。
- `Replicate` key 仅认 `.env`；`ScreenshotOne` key 仅在前端设置（URL 截图功能用）。

## 3. 主要功能

### 3.1 截图/设计稿 → 代码（核心功能）

**说明**: 拖入 1-5 张截图（PNG/JPG），选择技术栈，生成 4 个并行变体（多模型对比），实时流式预览。

**支持的技术栈**: HTML+Tailwind、HTML+CSS、React+Tailwind、Vue+Tailwind、Bootstrap、Ionic+Tailwind。

**使用流程**:
1. 首页 Upload 标签拖入截图（可补充文字说明）；
2. 选择栈与模型（生成设置里），点 Generate；
3. 等待流式生成——期间可看到模型思考（thinking）、工具调用（提取素材/写文件/截图自检）与代码逐字成形；
4. `Alt+1..9` 或点击缩略图切换变体，挑选最满意的；
5. 预览支持桌面(1366px)/移动(375px)切换、直接编辑代码（CodeMirror）、下载、Open in CodePen。

### 3.2 录屏 → 原型（video 模式）

**说明**: 上传 webm/mp4/mov（≤20MB）或用内置录屏（ScreenRecorder，`getDisplayMedia`）录制网站操作，转为可交互原型。**需要 Gemini key**，固定双变体。

### 3.3 文字 → 代码（text 模式）

**说明**: Text 标签直接输入产品描述生成页面；模型池与图片模式不同（`ALL_KEYS_MODELS_TEXT_CREATE`）。

### 3.4 URL 截图导入

**说明**: URL 标签输入网址（需在设置中配 ScreenshotOne key），后端 `POST /api/screenshot` 抓图后走图片流程。

### 3.5 迭代编辑（chat）

**说明**: 生成完成后，底部聊天框继续发指令（"把按钮改成蓝色"）。可附加截图、启用"选择元素编辑"（在预览里点选元素精准修改）。编辑走 2 个变体，携带当前代码与对话历史。

### 3.6 素材提取与图片工具（Agent 工具）

| 功能 | 条件 | 说明 |
|------|------|------|
| extract_assets 素材提取 | Gemini key + 图片模式 | 从截图抠出真实 logo/图片复用，默认开启（可关） |
| generate_images 图片生成 | 图片生成开关 | 占位图按提示词生成 |
| remove_backgrounds 去背景 | Replicate key | 批量去背景 |
| edit_images 图片编辑/放大 | Replicate key | 批量独立编辑 |
| screenshot_preview 截图自检 | Chromium 已装 | Agent 渲染自己的页面并视觉核对（设置页可见可用性） |
| save_assets | - | 用户上传图片存为可引用素材 |

### 3.7 设计系统（Design Systems）

**说明**: 设置/侧栏可管理设计系统（增删改查，存后端），生成时选用以约束风格。前端经 `GET/POST /api/design-systems`、`PATCH/DELETE /api/design-systems/:id` 管理。

### 3.8 版本历史

**说明**: 左侧 History 面板列出全部版本（创建/编辑/导入标记、分支来源、媒体缩略图）；点击任意版本回看，形成可切换的提交图。

### 3.9 评测系统（/evals）

**说明**: 前端内置 8 个评测页面（`/evals`、`best-of-n`、`run`、`sessions`、`compare`、`agent-runs`、`prompt-reports`、`openai-input-compare`），用于离线评估模型组合质量——项目的模型池就是靠这套评测刷新的（见 model_choice_sets.py 注释）。详见根目录 `Evaluation.md`。

### 3.10 导出

**说明**: `POST /api/export` 打包 zip（含素材），失败时回退为直接下载 index.html。

## 4. API 接口

后端默认 `http://127.0.0.1:7001`，OpenAPI 文档已关闭。

### 4.1 WebSocket

| 端点 | 说明 |
|------|------|
| `ws://…/generate-code` | 代码生成主通道；连接后发一次 JSON 参数，随后接收 `variantCount`/`status`/`chunk`/`thinking`/`assistant`/`toolStart`/`toolResult`/`setCode`/`variantComplete`/`variantError`/`error` 消息；关闭码 4332=后端已知错误、4333=用户取消、1000=正常完成 |

### 4.2 HTTP

| 接口 | 方法 | 说明 |
|------|------|------|
| `/` | GET | 首页（routes/home） |
| `/api/capabilities` | GET | 后端能力探测（截图预览可用性等），设置页调用 |
| `/api/screenshot` | POST | URL → 截图（ScreenshotOne） |
| `/api/export` | POST | 代码 + 素材打包导出 |
| `/api/design-systems` | GET/POST | 设计系统列表/创建 |
| `/api/design-systems/:id` | PATCH/DELETE | 设计系统修改/删除 |
| `/models`、`/eval-sets`、`/eval-sessions`、`/agent-runs`、`/run_evals_stream`、`/prompt-reports`、`/best-of-n-evals`、`/output_folders`、`/openai-input-compare` 等 | - | 评测体系端点（routes/evals、eval_sets、agent_runs、prompt_reports） |
| `/local-assets/*`、上传资源路由 | GET/POST | 本地素材与用户上传资源服务 |

**示例**:
```bash
# 探测能力
curl http://127.0.0.1:7001/api/capabilities
```

## 5. 测试

```bash
cd backend

```

## 6. 常见问题

### Q: 后端启动报 "No OpenAI, Anthropic, or Gemini API key"？
A: `backend/.env` 至少配一个 key（改完**重启后端**），或在前端设置对话框里填。视频模式额外强制要求 Gemini key。

### Q: Windows 下后端报 UTF-8 错误？
A: 用 Notepad++ 打开 `backend/.env` → Encoding → UTF-8 重新保存。

### Q: 如何配置 OpenAI 代理？
A: `backend/.env` 设 `OPENAI_BASE_URL`（路径须含 `/v1`，如 `https://xxx.xxx/v1`），或前端设置对话框；生产模式（IS_PROD）禁用。

### Q: 前端连不上后端？
A: 检查后端端口与 `frontend/.env.local` 的 `VITE_WS_BACKEND_URL`/`VITE_HTTP_BACKEND_URL` 是否一致；访问用 `http://localhost:5173` 而非 `127.0.0.1`。

### Q: 设置里 "Screenshot preview" 不可用？
A: 未装 Chromium。执行 `poetry run playwright install chromium` 后重启后端（启动时探测）。缺它只是少一个 Agent 自检工具，不影响主流程。

### Q: `edit_images`/`remove_backgrounds` 不可用？
A: 需要 `REPLICATE_API_KEY`，且**只认 backend/.env**，UI 设置无效。

### Q: GPT Vision 报模型不存在/无权限？
A: 见 Troubleshooting.md —— OpenAI 账户需充值并达到 Tier 1，新 key 可能要等约 30 分钟生效。

### Q: `pnpm install` 提示 "Ignored build scripts (esbuild, puppeteer)"？
A: 无害，可忽略（AGENTS.md 明确说明 Vite 构建与测试不受影响）。

### Q: 如何拿到 GPT-4/GPT-5 Vision 权限？
A: OpenAI Dashboard → Settings → Billing 充值（最低 $5）→ Limits 页确认 Tier 1 → 创建 api key。

## 7. 开发者须知（AGENTS.md 摘要）

- Python 命令一律 `cd backend && poetry run <command>`；
- 后端测试 + pyright 是每次改动的硬性检查；前端 `pnpm lint`；
- 多行提示词优先用三引号字符串/单个 f-string；
- 托管版在独立分支 `hosted`（连接 ../screenshot-to-code-saas）；
- Cursor Cloud 环境执行 `bash scripts/cursor-cloud-install.sh` 自动装依赖。
